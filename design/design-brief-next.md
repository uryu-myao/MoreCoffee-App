## 2a: pinned chips and group headings (built 2026-10-24; Uryu's)
- **What**: once the list scrolls past them, the category chips stay under the header rule, and each group heading (month, roaster…, with the sort's name) stays under the chips until the next heading pushes it up. Scrolling back, both return with the content. Your 2a board scrolls everything, so on a long list the chips went out of reach.
- **How it looks**: a pinned block hides the rows passing under it. It is `surface.ground` edge to edge with the page's dots drawn in it, lined up with the page's, so it reads as the page itself, not a band. (With no fill, the rows' text overlapped the chips and headings: Uryu, on device.) The hairline under a heading belongs to the heading now (2a's first row no longer draws it), so it stays while the heading is pinned. Report only; say if you see a problem.
